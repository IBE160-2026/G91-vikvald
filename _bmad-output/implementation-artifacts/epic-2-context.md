# Epic 2 Context: Emner, forelesninger og notater

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Let the student organise her semester: create, rename and delete subjects (with exam date) and lectures (with date), upload PDF notes after accepting the terms, get clear Norwegian messages for rejected files, delete and replace files with a confirmation that shows what disappears, and delete her whole account. This gives every later epic its data foundation (`subjects`, `lectures`, `files`, `file_pages`, `core/storage`) and the shared dialogs (delete confirmation, terms text, note surface) that content epics reuse.

## Stories

- Story 2.1: Opprett emner og se dem på forsiden
- Story 2.2: Legg til forelesninger og finn dem i sidemenyen
- Story 2.3: Last opp PDF-notater til en forelesning
- Story 2.4: Godta vilkårene før første opplasting
- Story 2.5: Slett filer, forelesninger og emner med bekreftelse
- Story 2.6: Erstatt en fil med en ny versjon
- Story 2.7: Se kontoen og slett den

## Requirements & Constraints

- Subject = name + exam date (required at creation, editable; past dates allowed). Lecture = name + date (defaults to today, editable). Lectures sorted by `date`, ties by `created_at`; subjects in creation order. Names are trimmed; empty/whitespace gives `NAME_REQUIRED` / «Skriv inn et navn.». Duplicate names are allowed.
- Ownership everywhere: another user's or a missing ID gives `404 NOT_FOUND` and the «Fant ikke siden» page.
- Upload: one or more PDFs per lecture, one file per API call. Reject with error code and nothing stored: `TERMS_NOT_ACCEPTED`, `NOT_PDF` (by content, not extension), `NO_READABLE_TEXT` (no text after stripping whitespace), `TOO_MANY_PAGES` (>50; exactly 50 OK; `details.page_count`), `FILE_TOO_LARGE` (>`MAX_UPLOAD_MB`, default 20; checked before PyMuPDF opens it, stop reading at the limit; `details.size_mb`), `PDF_UNREADABLE` (locked/corrupt). Rejection texts are used verbatim from the epics file / EXPERIENCE.md.
- Multiple files: accepted ones are stored; each rejected file gets its own message prefixed with its filename, announced in a live region, kept until next upload or leaving the page. Same-named files are both stored.
- Page numbers are PDF page numbers starting at 1, never printed page numbers.
- Terms must be accepted before the first upload. The text covers responsibility for the material, own notes/rights, no personal data, sending to Google's model with EU processing, and Google possibly logging requests for abuse detection. Same text in demo and real mode; demo mode adds «I demomodus sendes ingenting ut.».
- Delete file/lecture/subject/account only after a confirmation showing what goes with it; cancel deletes nothing (DB or disk). Account deletion leaves no rows or files for the user; the email can be re-registered; other users are untouched.
- Every new error code goes in both `core/errors.py` and the frontend message file (existing test enforces this). Tests carry requirement IDs (`test_fr6_…`, `test_fr39_…`, `test_nfr16_…`, `test_uxdr22_…`). Test PDFs are generated by the tests (PyMuPDF) or written in own words; no third-party material in the repo. axe with zero violations and full keyboard operation on every page/dialog touched.

## Technical Decisions

- **Modules:** `subjects` owns `subjects` + `lectures`; `files` owns `files` + `file_pages`; `identity` owns `users`. `content` owns all content counts. Only the owner module writes its tables. Tables are created by Alembic migrations in the story that first needs them, and must run on Postgres and SQLite.
- **Schema:** `subjects` (UUID, `user_id`, `name`, `exam_date` date, `color_index` 0–5, `created_at`); `lectures` (UUID, `subject_id`, `name`, `date`, `created_at`); `files` (UUID, `lecture_id`, `original_name`, `page_count`, `uploaded_at`); `file_pages(file_id, page_no, text, needs_image)` with `needs_image=false` for now (rule comes in epic 6); `users.terms_accepted_at` (UTC, nullable, set once). All FKs `ON DELETE CASCADE` from user downward; no row-by-row delete code.
- **Colour:** `color_index` set at creation to the first of six colours not used by her subjects; when all six are used, `count % 6`. Never changes.
- **API:** `POST/GET /api/subjects` (list includes `lecture_count`), `PATCH /api/subjects/{id}`, `POST/GET /api/subjects/{id}/lectures`, `PATCH /api/lectures/{id}`, `POST /api/lectures/{id}/files` (multipart), `POST /api/files/{id}/replace`, `POST /api/identity/terms` (idempotent), `GET /api/identity/me` (includes `terms_accepted_at`), `GET …/delete-preview` for files, lectures, subjects and `/api/identity/me`, `DELETE` for each plus `DELETE /api/identity/me` (clears `sk_session`, `204`). `201`/`204`, `snake_case`, ISO dates; display `dd.mm.åååå`.
- **Storage:** only `core/storage` touches disk, at `data/uploads/<user_id>/<file_id>.pdf` under `UPLOAD_DIR` (temp dir in tests), on a Docker volume `uploads`. Functions: save, read, delete one, delete user folder. Original filename only in the DB. Disk deletes happen after the transaction commits; a disk failure is logged (no file content) and the response is still `204`.
- **PDF parsing:** PyMuPDF (not pypdf) reads every page into `file_pages`.
- **Delete preview:** `content` has a registry where content types register a `kind` and a count function over sets of files/lectures. Empty in epic 2; later epics plug in without touching delete code. Preview returns lecture/file counts plus registry counts, omitting zeros.
- **Replace:** one call; validates the new file with all upload rules *before* deleting anything; on success old file removed and new one saved with a new `file_id` in one transaction; old PDF removed from disk afterwards.
- **Jobs:** none in this epic; epic 3 adds `409 JOB_ALREADY_RUNNING` to deletes.

## UX & Interaction Patterns

- **Front page (02):** h1 «Dine emner», outline button «Nytt emne», simple list (colour dot, name linking to 03, lecture count, «Eksamen 04.12.2026»), no sidebar. Empty state: one sentence about the app + primary «Lag ditt første emne». Epic 5 later replaces the list.
- **Subject page (03):** h1 name, «eksamen fredag 04.12.2026» line (later with lecture/file counts), «Ny forelesning», «Nytt navn», «Endre eksamensdato», «Slett emnet». `lecture-table`: Dato (`dd.mm`), Forelesning, Filer (right-aligned, «–» for 0), Status («Ikke øvd ennå» / «Ingen filer ennå»); whole row links to 04. Empty: «Ingen forelesninger ennå.».
- **Lecture page (04):** h1 name, «Forelesning fredag 11.09.2026 · 2 filer · 18 sider», «Nytt navn», «Endre dato», «Slett forelesningen». «Filer» section with `file-row` (icon, name, «12 sider · lastet opp 11.09», red «Slett», «Erstatt») sorted by upload time; `upload-zone` (dashed `border-control`, drag-and-drop + keyboard-usable «Velg PDF», multiple files, upload status in live region); privacy note below in shared `note-surface` (never used for errors).
- **Sidebar (`sidebar-tree`) on 03, 04, 15:** overline EMNER, subjects with dot (`aria-hidden`, name always shown), name, right-aligned count; open subject shows lectures as `menu-row` with ISO week number and a hollow status dot; `aria-current="page"` on the current item; truncated names keep full accessible name; subjects open/close by keyboard. «? Hurtigtaster» comes in epic 3.
- **Colours:** add `subject-4`–`subject-6` as Tailwind tokens, ≥3:1 against `paper` (#F8F7F3), away from brand (#3A3FB0), danger red and success green; Vitest checks contrast; record values in DESIGN.md; Silje approves. Subject colours only on dots/timeline, never buttons, surfaces or text.
- **Dialogs:** shared `dialog` (focus trap, Esc closes without change, focus returns to opener, «Avbryt» then primary). Form fields with visible label, red border + linked error text, focus moved to field; date errors «Skriv inn eksamensdatoen, for eksempel 04.12.2026.» / «Skriv inn datoen, for eksempel 11.09.2026.».
- **Delete confirmation (shared, 560 px):** title («Slette fila?», «Slette forelesningen?», «Slette emnet?», «Erstatte fila?», «Slette kontoen?»), a box naming the item, «Dette sletter også …» built by one `frontend/lib/` function with commas, «og», singular/plural, then «Det kan ikke angres.» (sentence omitted when everything is 0; never «0 …»). «Avbryt» has initial focus; danger button never does. After deleting a lecture → 03; subject → 02; account → login.
- **Terms dialog (05, 640 px):** opens on first file pick/drop, title «Før du laster opp», names the file (or count), checkbox enables «Godta og last opp», then the chosen files upload via the normal flow. Cancel/Esc/close uploads nothing. Terms text lives in one shared component also shown without checkbox on the account page.
- **Account page (15):** h1 «Konto», sidebar without selected lecture, demo badge in demo mode; cards Innlogging (email, «Lagret kryptert, aldri i klartekst», «Logg ut»), Vilkår og personvern (accepted date or «Ikke godtatt ennå…», model row, «Les vilkårene»), Slett kontoen (counts line, red-text outline button «Slett kontoen …»). No «logged in since» row.

## Cross-Story Dependencies

- 2.1 → 2.2 → 2.3 build the chain subjects → lectures → files; each adds its migration and extends 03/04 and the sidebar.
- 2.3 builds `core/storage`, the `uploads` volume, `note-surface` and the upload flow that 2.4 gates and 2.6 reuses for validation and messages.
- 2.4's shared terms component is reused by 2.7; `TERMS_NOT_ACCEPTED` applies to 2.3 uploads and 2.6 replacements.
- 2.5 builds the `content` count registry, delete-preview endpoints, the shared delete confirmation and the plural-sentence function, all reused by 2.6, 2.7 and epics 3, 4, 7–9.
- Relies on epic 1: `current_user`, 404 helper, error format/message file, `dialog`, `text-field`, buttons, top bar «Konto» link, logout flow.
- Later: epic 3 adds jobs (`409` on delete) and registers flashcards in `content`; epic 5 adds Kort/Quiz columns, filled status dots and replaces the front-page list; epic 6 sets the `needs_image` rule and the real-model privacy note text.

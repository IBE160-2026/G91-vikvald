# Epic 3 Context: Øv med flashcards

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Let the student generate flashcards from a lecture's notes, practise them with «Kunne» / «Kunne ikke» (missed cards come back), see and save the session result, practise a whole subject, and edit or delete bad cards. The epic builds the two engines every later content type plugs into: the generation pipeline in `generation` (LLM port, mock models, registry, validation, jobs) and the practice frame in `practice` (session panel, answer grid, result, session saving). Everything runs in demo mode with no keys or internet.

## Stories

- Story 3.1: Lag flashcards fra en forelesning i demomodus
- Story 3.2: Velg omfang og se hvordan genereringen gikk
- Story 3.3: Øv på flashcards fra én forelesning
- Story 3.4: Hurtigtaster, fokus og smal skjerm i økten
- Story 3.5: Lagre økten og se resultatet
- Story 3.6: Øv på flashcards fra hele emnet
- Story 3.7: Rett og slett kort, og se hva som slettes

## Requirements & Constraints

- **Language (real model):** generated content in Norwegian bokmål even from English notes; Norwegian terms kept as written; English term in parentheses when notes use both («merkevare (brand)»). Only material from the pages.
- **Card types:** `qa` (question + answer) and `concept` (term front, explanation back). Both rendered by the same card; term shown under SPØRSMÅL.
- **Mock rules (deterministic):** one `concept` card per definition sentence («X er …» / «X is …»): words before «er»/«is» on the front, the whole sentence on the back, `file_id` + `page_no` of that page, text taken unchanged from `file_pages`. Same file → identical output (tested with a fixed fixture in `backend/tests/fixtures/`). «+ Lag flere» skips cards whose front matches an existing card in the lecture; if nothing new, show the «nothing made» message and store nothing. Mock ignores the prompt file.
- **Limits:** `requested` is 10, 20 or 30 only (default 20; Rask/Vanlig/Dyp). If more valid items than requested, keep the first `requested` in fixed order (file, page, position on page). Timeout 3 minutes via `asyncio.wait_for` (tests lower it). One running job per lecture. No HTTP request may last over 30 s, so generation is always a job. Demo job of 20 cards < 5 s; real model normally < 2 min. No rate limiting/quotas in MVP.
- **Append, never replace:** new cards are added to existing ones.
- **All-or-nothing:** port failure, timeout or a failing save stores nothing; lecture count unchanged.
- **Ownership:** every route uses `current_user`; another user's lecture/subject/card → `404 NOT_FOUND`.
- **Sessions:** only the result is stored, never individual marks, and only if at least one card was marked. First mark per card counts. «Øvd»/SISTE ØKT logic is NOT built here (story 5.1 owns the single function).
- **Error codes** (add to `core/errors.py` and the frontend message file; existing test enforces both): `JOB_ALREADY_RUNNING` (409), `GENERATION_FAILED`, `GENERATION_TIMEOUT`, `JOB_INTERRUPTED`, a code for "lecture has no files" (name not fixed in planning), and codes for empty front/back on edit.
- **Tests** carry requirement IDs (`test_fr38_…`, `test_nfr2a_…`, `test_sk21_…`, `test_ar5_…`, `test_fr21_…`, `test_sk4_…`, `test_sk8_…`, `test_fr17_…`, `test_fr23_…`–`test_fr27_…`, `test_fr20_…`, `test_nfr8_…`, `test_uxdr26_…`, `test_uxdr10_…`, `test_fr56_…`, `test_sk20_…`, `test_ar9_…`, `test_sk6_…`, `test_fr12_…`, `test_ar7_…`). axe zero violations and full keyboard use on every page/dialog/state touched. Pytest runs with `LLM_PROVIDER=mock` on SQLite.
- **README / `.env.example`:** document `LLM_PROVIDER` (`mock`, `mock-invalid`) and state that demo content is simple and mechanical, showing that features work, not real-model quality.

## Technical Decisions

- **LLM port:** only `generation` calls a model, via `generate(kind, pages, options)` returning a *loose* list (fields may be missing) regardless of implementation. `LLM_PROVIDER` unset/`mock` → `MockGenerator`; `mock-invalid` → `InvalidMockGenerator` (deliberately invalid items, SK-4); any other value, including `vertex` (epic 6), stops startup with a clear log message. `VertexGenerator` (pydantic-ai, `GoogleCloudProvider(location='eu')`, `NativeOutput`) comes in epic 6.
- **Generation registry:** a new content type registers `kind` → mock rule, loose model, `validate_item`, and persistence through `content`, without changing the pipeline. `flashcards` is the first entry. `generation` owns loose models; `content` owns stored models and the `flashcards` table.
- **Pipeline:** fetch page text from `file_pages` → call port → `validate_item(item, pages)` per item → discard and count → save valid items in one transaction. Flashcard validation rejects empty front, empty back (for `qa`/`concept`), unknown `kind`, or `file_id`/`page_no` not in the lecture's files. Student edits are checked only for empty fields, never with `validate_item`.
- **Prompt file:** flashcard instructions live as a text file in `generation` (Norwegian rules above, source file + PDF page per card, `qa` and `concept`), ready for epic 6.
- **Schema (one migration in 3.1):** `jobs` (`id`, `lecture_id`, `kind` flashcards/quiz/models/freetext/summary, `params`, `status` running/done/failed, `requested`, `created`, `discarded`, `error_code`, `started_at`, `finished_at`) with a partial unique index on `lecture_id` where `status='running'` (both `postgresql_where` and `sqlite_where`). `flashcards` (`id`, `file_id` `ON DELETE CASCADE`, `kind` `qa`/`concept`/`model`, `front`, `back` nullable only for `model`, `page_no`, `formula_flag`, `created_at`). Story 3.5 adds `practice_sessions` (`session_id` unique, `subject_id`, nullable `lecture_id`, `kind`, `aborted`, `shown`, `answered`, `correct`, `partial`, `wrong`, `started_at`; cascade from subject and lecture; no `user_id`, ownership via subject).
- **Jobs:** `POST /api/lectures/{id}/jobs` `{kind, params:{requested}}` → `202` with the job (`status="running"`); runs as an asyncio task with its own DB session in a single Uvicorn process. On startup `running` jobs become `failed`/`JOB_INTERRUPTED` before Uvicorn serves (after migrations and seed). No valid items → `done` with `created=0`. Jobs continue after logout. Status endpoints: `GET /api/lectures/{id}/jobs/latest` (latest per `kind`), `GET /api/jobs/active` (current user only), `GET /api/jobs/{id}`.
- **Other API:** `GET /api/lectures/{id}/flashcards`, `GET /api/subjects/{id}/flashcards` (adds lecture name), `PATCH`/`DELETE /api/flashcards/{id}`, `POST /api/practice-sessions` (JSON or `text/plain`, idempotent via `ON CONFLICT DO NOTHING` for both DBs). Content has `source: {file_id, file_name, page_no}`; `page_no` is the PDF page from 1. Generated content is rendered as plain text, never HTML.
- **Session saving:** browser creates `session_id` (UUID), counts `shown` (distinct cards shown), `answered`, `correct` («Kunne»), `wrong` («Kunne ikke»), and sends `duration_seconds`; server sets `started_at = received − duration`. Sent exactly once on finish, «Avslutt økt»/Esc, in-app navigation, before logout («Logg ut» waits), and `pagehide` via `sendBeacon`; `aborted=true` except on finish. Subject session: `lecture_id` empty.
- **Deletes:** flashcards register in the `content` delete-preview registry (file, replace, lecture, subject, account). Deleting/replacing a file or deleting a lecture, subject or account while a job runs on an affected lecture → `409 JOB_ALREADY_RUNNING`, nothing deleted.
- **Frontend:** shuffling and the «Kunne ikke to the back» queue are pure functions in frontend module `practice` (Vitest). `session-panel` takes a per-type adapter so quiz/freetext reuse it. Shortcut handling is one shared function in `frontend/lib/`, active only during practice. Shared components go in `frontend/components/`: `create-row`, `job-status`, `source-link`, reusing `note-surface`, `dialog`, `choice-option` and the delete confirmation from epic 2.

## UX & Interaction Patterns

- **«Lag og øv» on 04 (`create-row`):** with cards «24 kort», primary «Øv nå», text button «+ Lag flere»; without «Ingen ennå» and outline «Lag flashcards»; no files → disabled with «Last opp notater først.». Waiting state when another row's job runs: «Venter til flashcardene er ferdige». «Øv nå» only when cards exist.
- **`job-status`:** spinner, «Lager flashcards …», «Du kan bruke resten av appen imens.»; start/end announced in a live region. Done → «Øv nå» and new count return without reload.
- **Outcome messages (approved, verbatim):** fewer: «Det ble laget 12 av inntil 20 flashcards. Notatene ga ikke grunnlag for flere.» on `note-surface` (never used for errors), stays until next flashcard job; none found: «Notatene ga ikke grunnlag for flashcards. Ingenting er lagret.»; failure (error, timeout, interrupted): «Vi klarte ikke å lage flashcardene. Ingenting er lagret. Prøv igjen.» + «Prøv igjen» (same scope); toast on other pages (sonner, live region, cuttable): «Flashcardene er ferdige: 18 kort i Uke 37: Merkevare.».
- **Dialog «Lag flashcards» (cuttable):** lecture with file/page counts, «Nye kort legges til de 24 du har fra før.», choice cards «Rask / Inntil 10 kort», «Vanlig / Inntil 20 kort» (preselected), «Dyp / Inntil 30 kort» (arrow keys), «Tar noen sekunder.» (demo) / «Tar vanligvis under to minutter.», «Du kan bruke resten av appen imens.», buttons «Avbryt» then «Lag flashcards»; Esc closes, focus returns.
- **Session 07:** practice layout, `session-panel` replaces the sidebar, card centred in 768 px. Unflipped: overline SPØRSMÅL, «Kunne ikke»/«Kunne» equal width and disabled; flip by click/button/Space shows SVAR under a hairline (no animation or short one off under `prefers-reduced-motion`), `source-link` as plain text «merkevare-notater.pdf, side 4», «Rediger»/«Slett» text buttons in the footer. Card list locked at session start. Empty session URL: «Det finnes ingen flashcards her ennå.» + «Tilbake til forelesningen».
- **Session panel:** ØKT, «Flashcards», lecture name (subject: «Markedsføring · hele emnet»), counter of distinct cards never above total («24 / 24»), «Repeterer: 3 kort igjen», progress bar, «Kunne 5 · Kunne ikke 1», answer grid (6 per row, ✓/✗, current cell ultramarine border, not buttons, read as «Kort 4: kunne ikke», text alternative; hidden above 120 cards), legend «Kunne», «Kunne ikke, kommer igjen», «Ikke vist ennå», outline «Avslutt økt» (no confirmation; nothing marked → straight back). Finished: «✓ Økten er ferdig og lagret», legend «Kunne ikke, repetert», «Økten er ferdig» announced.
- **Shortcuts:** Space flip, `1` Kunne ikke, `2` Kunne (after flip), Esc end, `?` dialog; never in text fields; Esc with a dialog/overlay open closes only that; Space on a focused button does the button's action; focus never auto-moves to «Avslutt økt». After flip focus → «Kunne»; after mark → next card. Hint line (`kbd`, text): «Mellomrom snu kortet», «1 Kunne ikke», «2 Kunne», «Esc avslutt». Shortcut dialog from «? Hurtigtaster» with toggle «Bruk hurtigtaster» (default on, `localStorage`, on if unreadable; off hides hint line).
- **Narrow (≤768 px or 200 % text):** panel/sidebar behind a top-bar menu button, overlaying content, no horizontal scroll; also applies to epic 2 pages (front-page cards wait for epic 5).
- **Result 08 (cuttable):** «ØKT FERDIG», «Du har gått gjennom alle 24 kortene», «Uke 37: Merkevare · kortene du ikke kunne, ble repetert til slutt i økten», «Kunne 19» / «79 % av kortene», «Kunne ikke 5» / «Repetert til slutt i økten», no celebration; aborted title «Avbrutt etter 12 av 20»; `missed-list` «Kortene du ikke kunne» with number, question, source. «Øv igjen»/Enter (new shuffle, new `session_id`), «Tilbake til forelesningen»/Esc to where the session started (subject page for subject sessions).
- **Subject page 03:** `practice-all-card` «Øv på hele emnet» with Flashcards row «120 kort fra 6 forelesninger» + primary «Øv på flashcards»; row hidden when no cards; built for quiz/freetext rows later.
- **Edit/delete card:** dialog with labelled fields «Spørsmål» and «Svar», «Lagre» (`PATCH`), errors «Skriv inn spørsmålet.» / «Skriv inn svaret.» (red border, linked text, focus), Esc no change; delete uses the shared confirmation with the card's question, «Det kan ikke angres.», «Avbryt» focused, danger «Slett kortet». A deleted unmarked card leaves the grid and total; a marked one keeps its first mark. File delete text e.g. «Dette sletter også 18 flashcards laget fra fila. Det kan ikke angres.»; job blocking text «Det lages innhold i denne forelesningen nå. Vent til det er ferdig, og prøv igjen.».
